# One free MAB account across the apps

All five apps use the existing user pool `us-east-2_VzCBot5S3`, the same private profile table, and one account API. Each app has a public OAuth client with its own callback. A user registers once, verifies their email, and completes their MAB profile once. Cognito reuses its browser sign-in session when another app automatically checks their shared sign-in session.

The two entry buttons are **Create free account** and **Sign in**. Registration goes straight to [Cognito's `/signup` page](https://docs.aws.amazon.com/cognito/latest/developerguide/managed-login-endpoints.html) with PKCE and state generated by `oidc-client-ts`.

FeGenie's `#/` fragment is an application route, not part of its OAuth callback. The original hash route is restored after login. Result codes in the other apps' `?result=` links are restored too. TaxonSleuth's genome handoff is captured by GToTree before login and consumed afterward.

Full name and verified email come from Cognito. Institution/company and position are required by the shared API before any app access. Favorite software and research area are optional. Users may enter Independent as their institution. Administrators in `mab-admin` can see/export profiles. Other members cannot access those records.

## Deploy

Merge the coordinated PRs in **gtotree-app, assembly-grasp-app, fegenie-app, breseq-app and basil-app** before enabling authentication. Their existing auto deployments can complete with authentication disabled.

In **AWS CloudShell, us-east-2**, from the updated `gtotree-app` checkout:

```bash
git pull --ff-only
bash accounts/deploy-all.sh
```

If this is a new CloudShell checkout, clone the repository first through your normal GitHub access. This script:

1. Reads each Amplify app's current global/main environment variables and matches its existing Lambda Function URL. Missing/unsupported configurations stop with an error; bucket names are not guessed.
2. Creates/reuses four public OAuth clients in the same pool, with code grant, `openid email profile`, and no client secret. Adds default managed-login branding if the domain uses branding version 2. The GToTree client is retained.
3. Updates the existing `mab-accounts` stack with the clients, origins, app routes and scoped S3/Lambda permissions. The Cognito pool and profiles table are retained.
4. Sets `VITE_MAB_AUTH_ENABLED=true`, `VITE_MAB_API_BASE` and the app's own `VITE_MAB_CLIENT_ID` on each main branch; starts all five Amplify builds.

Save the generated `accounts/apps.local.json`, `accounts/deploy-parameters.local.json` and `accounts/amplify-before-accounts.local.json` privately in CloudShell. They are ignored by git. Repeat deployments reuse these clients and settings. Do not replace individual legacy `VITE_*_API_BASE` values with the account URL; they support inventory and rollback.

The script changes AWS account resources and starts deployments when you run it. It leaves legacy public services and buckets open until the final cutover below.

## Test before closing public access

After all five builds succeed, test in an incognito browser:

- Create a free account, verify email, and finish the required profile. Test a second app with the same email/account.
- Search TaxonSleuth, select genomes, and transfer them to GToTree. Test the transfer when GToTree needs sign-in.
- Submit one small job per analysis app. Confirm it reaches the existing worker, finishes, and its report/downloads work. Worker installation/restarts are not required by this change.
- Open an existing result code using a different complete MAB account. This is intentionally allowed. Test FeGenie deep links, BASIL plots/PDFs, and breseq evidence links/images.
- Check that incomplete profiles and signed-out requests to the account API cannot read/upload results; ordinary users cannot list profiles.

Then, from the same checkout:

```bash
python3 accounts/private-apps.py --apply
```

This closes the five old anonymous Lambda URLs and enables all S3 public-access blocks on the configured input/results buckets. TaxonSleuth's underlying search Lambda remains callable through the account API's IAM role. Bucket contents and worker IAM access are unchanged. The script backs up access settings and prints the exact rollback command. Without `--apply`, it only audits.

After cutover, repeat the report/download tests and check that the old service URLs and unsigned S3 object URLs fail. Previously issued signed URLs remain usable until they expire.

## Result access

Any verified, profile-complete MAB user with a code can access that result. Codes are shareable within the MAB account community; there is no owner-only read restriction. No API lists every result code.

The account API authenticates every search, submission, result listing and streamed artifact request. It records usage with the correct app name. It does not return raw logs, submission manifests, raw FASTQ reads, diagnostic archives, or unsanitized worker errors. GToTree's existing scientific-file policy is retained. The other apps use explicit scientific output directories/file names.

For BASIL images/PDFs and other scientific downloads, the API issues **15-minute signed S3 links** after checking the account. These links are temporary bearer links: anyone given one can use it until expiration, even without signing in. Buckets remain private. Share the app's result-code link for durable sharing and account enforcement. HTML reports are fetched with Authorization and rendered in an opaque sandbox; tokens are never put in result URLs or exposed to report scripts. breseq's relative evidence links are resolved through the authenticated viewer.

For frontend rollback, restore each main branch's saved environment variables (or set `VITE_MAB_AUTH_ENABLED=false`) and redeploy. If public access has already been closed, first use the cutover script's printed rollback command. Existing legacy APIs remain available for this rollback.
